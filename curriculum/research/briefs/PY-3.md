§1 (the problem): numerical code is full of "do this to that function" — integrate f, find a root of g, time h, cache the expensive k — and without functions as values you end up copy-pasting the integrator for every f. The forcing problem: you have six root finders and ten functions to test them on, and the clean solution is a function that takes functions. §2 (the intuition): a function is an object like any other — it has a name binding, can sit in a list, be passed in, be returned; a closure is a function that carries a backpack of the variables that were in scope when it was made; a decorator is a function that takes a function and hands back a wrapped version; a module is just a file whose top-level names become attributes of an object when imported, and importing runs the file once.

Topics in order: functions as objects (`type(f)`, attributes, storing in dicts — the dispatch-table idiom replacing long `if/elif` chains); higher-order functions — passing and returning functions, `map`/`filter`/`functools.reduce` vs comprehensions (prefer comprehensions; know the others), `sorted(key=...)` as the everyday higher-order function, `lambda` (one expression; when a `def` is clearer); closures — free variables, `__closure__`, the late-binding trap in loops (`[lambda: i for i in range(3)]`) and its default-argument fix, `nonlocal` for a counter closure; decorators — the wrapper pattern derived step by step from "I want to time every call", `@` syntax as sugar, `functools.wraps`, decorators with arguments (three levels), `functools.lru_cache` and `functools.cache`, `functools.partial`; argument handling — `*args`, `**kwargs`, keyword-only (`*`) and positional-only (`/`) parameters, argument unpacking at the call site, why `def f(x, lst=[])` is still wrong; recursion — base case and recursive case, the call stack drawn as frames, `sys.getrecursionlimit`, memoization turning exponential Fibonacci into linear, divide and conquer (merge sort, binary search), the recursive cofactor determinant (LA-6) and its O(n!) cost as a lesson in why you should not, mutual recursion in one paragraph, when iteration is better; generators revisited as resumable functions; modules — what `import` does (find, execute once, bind; `sys.modules`), `from m import name`, `import m as alias`, why `from m import *` is banned here, `if __name__ == "__main__":`, `python -m module`, `sys.path` and why "it works in the REPL but not from the script" happens, packages (`__init__.py`, subpackages, relative imports), `__all__`; the standard-library tour with one example each: `math`, `cmath`, `fractions`, `decimal`, `random` (seeding; `random.Random` instances), `statistics`, `time` (`perf_counter`), `datetime`, `os`/`sys`, `argparse` (a real CLI with positional and optional arguments, types, help), `re` (match/search/findall/sub, raw strings, groups — enough to parse a log line), `textwrap`, `pprint`; environments — `python -m venv`, `pip install`, `pip freeze`, why environments exist.

Build-it-yourself sequences: (1) from a copy-pasted timing block to a `@timer` decorator in five steps, adding `functools.wraps` when `__name__` breaks; (2) `@memoize` with a dict, then compare with `lru_cache`, then the hashability requirement; (3) the late-binding trap — predict, run, fix with a default argument, fix with `functools.partial`; (4) `compose(f, g)` and `pipeline(*fs)` returning functions; (5) the call stack for `fib(4)` drawn frame by frame, then memoized; (6) binary search recursive and iterative with the invariant stated; (7) a `numtools` package: layout, `__init__.py` exports, a `__main__.py`, run with `python -m numtools`; (8) an `argparse` CLI built from a bare script in four steps.

Worked examples (≥6): a dispatch table of string → function for a calculator; a closure counter with `nonlocal` and its state inspected via `__closure__`; `@timer` applied to the PY-1 root finders; `lru_cache` on Fibonacci with `cache_info()` output; a regular expression parsing `2024-03-01T12:00:00 sensor_7 23.5` into fields; a CLI run with `--help` output shown.

Project: the `numtools` package in a subfolder of the module (the writer may create `numtools/` inside the module folder; project.py imports it with a `sys.path` adjustment or relative placement and explains why) containing the PY-1 root finders and PY-2 sparse polynomial, decorators `timer`, `memoize`, `retry(n)`, a `compose`/`pipeline`, and a CLI (`python -m numtools bisect "cos(x)-x" 0 1`) — project.py exercises all of it: timing table for root finders; naive vs memoized Fibonacci timings plotted (log scale) with the exponential vs linear growth asserted (ratio of times at n = 25 vs n = 20 for naive ≈ φ⁵ ≈ 11, within a factor of 2); recursive cofactor determinant vs `numpy.linalg.det` for n = 2…7 asserted (with timing growth showing factorial behavior); merge sort vs `sorted` agreement on 10⁴ random items; `re`-based log parsing asserted on 1000 generated lines. "Your turn": a decorator that counts calls; `lru_cache` with a `maxsize` and a hit-rate measurement; convert a recursive function to iterative with an explicit stack; add a subcommand to the CLI.

§8 honest: the late-binding closure trap will bite you in a plotting loop within a month; decorators are simple once you have written one by hand and baffling until then — do not skip the build-it-yourself; `functools.wraps` is not optional; recursion depth of ~1000 means Python is not the language for deep recursion — know the limit; `sys.path` confusion ("module not found" when the file is right there) is the most common import error and it is about *where you ran Python from*; `from module import *` hides where names come from and shadows built-ins; `random.seed` at module import time is a footgun — pass a `Random` instance or a `rng` argument instead.
