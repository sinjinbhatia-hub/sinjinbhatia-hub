# Brief: PY-4 — Classes and the object model: dunder methods, dataclasses, protocols, and a dual-number automatic differentiator
Folder: curriculum/00-python/04-classes-and-the-object-model/ · ~10 hours · prereqs PY-3 (LA-1 helpful for the Vec example) · unlocks PY-5, PY-6 (ndarray is a class with these dunders), LA-14 and ML-2 (the dual-number AD is their preview)

Conventions: as PY-1; `__repr__` returns something that could be typed back in; `__eq__` with `__hash__` always considered together; third-party imports: numpy and sympy in the project for cross-checks only (the classes are pure Python).

Read the PY addendum in research/WRITER-BRIEF.md first.

§1 (the problem): a 3-vector as a list `[x, y, z]` has no `+`, no `|v|`, no dot product, and `v * 2` repeats the list; a derivative computed by finite differences is noisy and needs a step size. Both problems have the same fix: define a new kind of object that knows how to behave under the operators Python already has. The forcing problem is operator overloading for a type the language does not ship — and the payoff example is a number that carries its own derivative. §2 (the intuition): a class is a blueprint; an instance is a dict of attributes plus a pointer to the class; `a + b` is `type(a).__add__(a, b)` — operators are method calls with special names, so you can teach any object to add, compare, index, iterate, or be called; "duck typing" means Python asks "can it quack?" at call time, not "is it a Duck?" at definition time.

Topics in order: defining a class — `__init__`, `self` demystified (the instance is passed explicitly; `obj.method()` is `Class.method(obj)`), instance vs class attributes and the lookup order, methods, `__repr__` vs `__str__` (and which the REPL uses), `__eq__` and the `__hash__` contract (equal objects must hash equal; defining `__eq__` sets `__hash__` to `None`), `__lt__` and `functools.total_ordering`; arithmetic dunders — `__add__`/`__sub__`/`__mul__`/`__truediv__`/`__pow__`/`__neg__`/`__abs__`, the reflected versions (`__radd__`, `__rmul__` — why `2 * v` needs it), `NotImplemented` and how Python tries both sides, in-place `__iadd__`, `__matmul__` for `@`; container dunders — `__len__`, `__getitem__` (including slices), `__setitem__`, `__iter__`/`__next__`, `__contains__`, `__bool__`; `__call__`; properties — `@property`, setters, computed attributes, validation; `@classmethod` (alternative constructors like `Vec.from_polar`) and `@staticmethod`; `@dataclass` — fields, defaults and `field(default_factory=...)`, `frozen=True`, `order=True`, generated `__repr__`/`__eq__`, when to use it (most data-holding classes) and when not; inheritance — `super()`, method overriding, `isinstance`, when inheritance is right (is-a with shared behavior) vs composition (has-a), the fragile-base-class smell; abstract base classes (`abc.ABC`, `@abstractmethod`), `collections.abc` (Sequence, Iterable) and what you get for free; protocols and duck typing — `typing.Protocol`, structural typing, why NumPy accepts anything with `__array__`; `__slots__` in one paragraph; class design rules of thumb (small, one responsibility, prefer immutability, implement `__repr__` first).

Build-it-yourself sequences: (1) `Vec` for 2D/3D from a bare class to full arithmetic — add `__repr__`, `__eq__`, `__add__`, `__mul__`, discover `2 * v` fails, add `__rmul__`, add `__abs__`, `dot`, `cross`, `__iter__` so `x, y, z = v` works; then compare with LA-1's definitions; (2) `Rational` with gcd normalization, `__eq__`/`__hash__`, ordering, arithmetic — then compare with `fractions.Fraction`; (3) the centerpiece: `Dual` numbers a + bε with ε² = 0 — derive the rules (a+bε)(c+dε) = ac + (ad+bc)ε, division, powers, then `exp`, `sin`, `cos`, `log` via a small `dmath` module — and show that evaluating f(Dual(x, 1)) gives f(x) and f′(x) exactly in one pass (forward-mode automatic differentiation; cite LA-14 for the Jacobian view and ML-2/ML-7 for where this becomes backpropagation); (4) `Matrix` in pure Python (list of lists) with `__matmul__`, `__getitem__((i, j))`, transpose, and LU solve (LA-2), compared against numpy; (5) `@dataclass(frozen=True)` for a `Measurement(value, unit, time)` and a `Polynomial` with `__call__`; (6) an `Integrator` ABC with `Trapezoid` and `Simpson` subclasses vs a composition design taking a rule function — discuss which is better and why.

Worked examples (≥6): `obj.method()` traced to `Class.method(obj)` with `id`s; the `__eq__`-without-`__hash__` surprise (`TypeError: unhashable type`); `Vec` arithmetic including the `__rmul__` failure and fix; `Dual` differentiating f(x) = x·sin(x)/(1 + x²) at x = 1.3, asserted against sympy to 1e-14; `Matrix` LU solve on a 3×3 system vs numpy; a `@dataclass` with `order=True` sorting a list of measurements.

Project: `Vec`, `Rational`, `Dual` (+ `dmath`), `Matrix` as classes in project.py or an adjacent module; tests as asserts: `Vec` against LA-1 identities (Cauchy–Schwarz, parallelogram law numerically), `Rational` against `fractions.Fraction` on 1000 random pairs, `Dual` derivatives of ten functions against sympy (`lambdify`) and against central finite differences (show the finite-difference error floor near 1e-8 vs Dual's 1e-15 — plot error vs step size h with the V-shaped curve; this is the honest reason AD exists), the Jacobian of a vector function via one `Dual` pass per input (LA-14 preview), Newton's method using `Dual` for the derivative (ties to PY-1), `Matrix` LU vs `numpy.linalg.solve` on random 6×6 systems. "Your turn": add `__getitem__` with slices to `Vec`; a `Complex` class and comparison to built-in `complex`; a `Dual` with `__pow__` for non-integer exponents; second derivatives by nesting `Dual(Dual(...))` (hyper-dual numbers).

§8 honest: `self` is confusing for exactly one week and then obvious; forgetting `__rmul__` and `NotImplemented` makes your type half-work and the bugs are silent; `__eq__` without `__hash__` breaks sets and dict keys with a confusing error; inheritance is overused — composition is usually right and students reach for subclassing because it is the thing they were taught; dataclasses remove 80% of boilerplate and people still write `__init__` by hand; mutable default fields in dataclasses raise an error for a reason; AD by dual numbers feels like a magic trick — it is just the product rule stored in a tuple, and seeing that is the point.
