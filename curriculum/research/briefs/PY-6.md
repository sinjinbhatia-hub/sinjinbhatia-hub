§1 (the problem): a Python loop over 10⁷ floats takes seconds; the same operation in C takes milliseconds. A list of Python floats is a list of pointers to boxed objects scattered in memory; a NumPy array is a contiguous block of raw doubles with a shape and a dtype, and operations on it run as compiled loops. The forcing problem: the random-walk ensemble from F5 (10⁴ walkers × 10³ steps) is unbearable with lists and instant with arrays — but only if you stop writing loops, and that requires a new way of thinking about computation: whole arrays at a time. §2 (the intuition): an array is a block of memory plus a recipe (shape, strides, dtype) for reading it; slicing changes the recipe, not the memory, so slices are views that alias the original; broadcasting stretches a smaller array along missing or length-1 axes without copying; `axis=k` means "collapse axis k"; vectorization means expressing the loop you would have written as a sequence of whole-array operations.
