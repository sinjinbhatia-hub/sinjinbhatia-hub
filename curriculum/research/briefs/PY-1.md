§1 (the problem): the reader can already make Python do things, but cannot predict what it will do — why `b = a; b.append(1)` changes `a`, why `0.1 + 0.2 != 0.3`, why a function's default list "remembers" earlier calls. The forcing problem of this module is the gap between writing code that runs and knowing what the interpreter is doing. Everything downstream (NumPy views, class design, debugging) depends on closing it in week 1. §2 (the intuition): names are labels tied to objects, not boxes holding values — draw the diagram in text (name → arrow → object with id, type, value); assignment never copies; the call stack as a stack of frames each with its own names; a float as a point on a grid that gets coarser away from zero.

Topics in order: running Python three ways (REPL, `python3 file.py`, `python3 -i file.py`) and reading a traceback bottom-up (make this a full worked example; it is the most-used skill in the course); everything is an object — `type`, `id`, `is` vs `==`, immutability (int, float, str, tuple) vs mutability (list, dict, set), the names-and-values model with aliasing demonstrated and the mutable-default-argument trap explained from it; integers (arbitrary precision, `//`, `%` with negatives, `divmod`, `**`, bit operations in one paragraph); floats: IEEE 754 double in plain words — sign, 11-bit exponent, 52-bit fraction — machine epsilon (find it by a loop), spacing of representable numbers (`math.ulp`, `math.nextafter`), why `0.1` is not 0.1 (`Decimal(0.1)` and `(0.1).hex()`), comparison with `math.isclose` and absolute vs relative tolerance, catastrophic cancellation (the quadratic formula for b² ≫ 4ac and the stable rewrite — this is LA-13's subject in miniature; cite LA-13 as the destination), overflow to `inf`, `nan` and why `nan != nan`, summation error and Kahan summation (build it); complex numbers (`1j`, `abs`, `cmath`; one paragraph, pointer to F1); `bool`, truthiness of empty containers and zero, short-circuit `and`/`or` and the `x or default` idiom; strings as immutable sequences — indexing, slicing, `len`, methods (`split`, `join`, `strip`, `replace`, `startswith`, `format`-spec mini-language in f-strings: width, precision, `e`, `g`, `,`, alignment); `if/elif/else`, `while` with `break`/`continue`/`else`, `for` over `range` (half-open intervals and why), nested loops, the accumulator pattern; functions: definition, parameters, `return` (and implicit `None`), positional vs keyword arguments, defaults (evaluated once — the trap again, now explained), docstrings, pure vs side-effecting functions; scope: LEGB, why assignment inside a function creates a local, `global` and `nonlocal` and why to avoid them, closures previewed (PY-3); style: PEP 8 in ten rules, naming, line length, comments that say why.

Build-it-yourself sequences (replace derivations; each is numbered steps with ▶ Try it first / ■ What just happened): (1) the names-and-values model — predict the output of eight short aliasing snippets before running them, culminating in the mutable default; (2) find machine epsilon by halving until `1 + eps == 1`, then confirm `sys.float_info.epsilon`; (3) the quadratic formula — show the catastrophic cancellation numerically for b = 1e8, a = c = 1, derive the stable form by rationalizing, verify; (4) bisection root finding from the intermediate value theorem to a working function with a tolerance and an iteration cap, then Newton's method with the derivative passed in as a function (first taste of functions as values); (5) Horner's rule for polynomial evaluation from the nested form, with an operation count; (6) Kahan compensated summation — derive the compensation step, then measure error vs naive on 10⁷ terms of 0.1.

Worked examples (≥6, complete programs with real output): reading a four-frame traceback and fixing the bug; the aliasing diagram for `a = [1, 2]; b = a; c = list(a)`; `0.1 + 0.2` through `Decimal` and `.hex()`; formatting a table of values with f-string specs; bisection on cos x = x with the iteration table; the mutable-default bug and its `None` sentinel fix.
