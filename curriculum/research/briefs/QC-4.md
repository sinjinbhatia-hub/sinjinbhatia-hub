# Brief: QC-4 — Early algorithms: Deutsch–Jozsa, Bernstein–Vazirani, Simon; query complexity and interference
Folder: curriculum/05-quantum-computing/04-early-algorithms/ · ~10 hours · prereqs QC-2 (oracles U_f, phase kickback, Hadamard transforms, uncomputation) · unlocks QC-5, QC-6
Pair with: Mermin ch. 2–3; Nielsen & Chuang §1.4; Kaye, Laflamme & Mosca *An Introduction to Quantum Computing* ch. 6; Aaronson's lecture notes "Quantum Computing Since Democritus" ch. 10 (free online drafts) and his 2018 UT notes on query complexity; Simon (1994) original paper (short and readable).
Conventions: n-qubit inputs x ∈ {0,1}ⁿ; bitwise inner product x·y = Σx_iy_i mod 2; the Hadamard transform H^{⊗n}|x⟩ = 2^{−n/2}Σ_y(−1)^{x·y}|y⟩; the bit oracle U_f|x⟩|y⟩ = |x⟩|y ⊕ f(x)⟩ and the phase oracle O_f|x⟩ = (−1)^{f(x)}|x⟩; query complexity counts oracle calls; classical deterministic vs randomized (bounded-error) query complexity; ⊕ is XOR; Simon's hidden string s.

§1: Deutsch (1985) found the first problem where a quantum computer uses fewer queries than any classical one (one query vs two to learn f(0) ⊕ f(1)); Deutsch and Jozsa (1992) made the gap exponential against deterministic classical algorithms; Bernstein and Vazirani (1993) gave a gap against randomized ones; Simon (1994) gave an exponential separation against randomized algorithms for a problem with hidden structure — and his paper directly inspired Shor (QC-5) weeks later. The forcing problem: QC-2 established that n qubits have 2ⁿ amplitudes but only n bits come out; the question "can that ever help?" needed a clean, provable answer, and query complexity (count oracle calls, ignore everything else) is the setting where speedups can be proved rather than conjectured. §2: put the input register in uniform superposition, call the oracle once in phase form (phase kickback, QC-2), and every input's f-value is now written into a sign; a second Hadamard transform makes those signs interfere, and for problems with the right structure (a global property of f, like "constant or balanced" or "linear with hidden coefficients" or "periodic under XOR") the interference concentrates all amplitude on an answer that reveals the property — the Hadamard transform is the Fourier transform over the group Z₂ⁿ (F3's finite Fourier analysis), and these algorithms are Fourier sampling.

Topics in order: QUERY COMPLEXITY: the black-box model, why it's useful (provable lower bounds), deterministic, randomized (bounded error), and quantum query complexity defined; the bit oracle and its unitarity (QC-2), the PHASE ORACLE via kickback with the |−⟩ ancilla (derive U_f|x⟩|−⟩ = (−1)^{f(x)}|x⟩|−⟩ — every step), the ancilla remains unentangled (prove), so we write O_f; THE HADAMARD TRANSFORM: H^{⊗n}|x⟩ = 2^{−n/2}Σ_y(−1)^{x·y}|y⟩ derived by induction on n (or from the single-qubit formula H|b⟩ = (|0⟩ + (−1)^b|1⟩)/√2 and the tensor product), H^{⊗n} is its own inverse (prove via Σ_y(−1)^{(x⊕x')·y} = 2ⁿδ_{xx'} — the orthogonality of characters, F3/F1's roots-of-unity sum with ±1), the interpretation as the Fourier transform on Z₂ⁿ (characters χ_x(y) = (−1)^{x·y}; F3's finite Fourier analysis restated for this group — make this explicit, it's what generalizes to QC-5's QFT on Z_N); DEUTSCH'S ALGORITHM (n = 1): the circuit, the full state at each step (derive), output 0 iff f constant, one query vs two classically (prove the classical lower bound: one query of f(0) says nothing about f(1)), the interference picture (amplitudes for the two branches add or cancel); DEUTSCH–JOZSA: the promise (f is constant or balanced), the algorithm H^{⊗n} O_f H^{⊗n}, the amplitude of |0ⁿ⟩ at the output = 2^{−n}Σ_x(−1)^{f(x)} (derive), which is ±1 if constant and 0 if balanced (prove), so one query decides; the classical deterministic lower bound 2^{n−1} + 1 (prove by adversary argument), and the HONEST CAVEAT: a randomized classical algorithm with k queries errs with probability ≤ 2^{1−k} (derive), so the exponential separation is only against deterministic algorithms — Deutsch–Jozsa is a demonstration, not a useful speedup; BERNSTEIN–VAZIRANI: the problem (f(x) = s·x mod 2 for hidden s ∈ {0,1}ⁿ), the same circuit outputs |s⟩ with certainty (derive: the phase state is H^{⊗n}|s⟩ up to normalization, and H^{⊗n} inverts it), one quantum query vs n classical queries even with randomization (prove the classical lower bound by the information-counting argument: each query reveals at most one bit about s), the recursive Bernstein–Vazirani problem and the superpolynomial separation named; SIMON'S ALGORITHM: the problem (f: {0,1}ⁿ → {0,1}ⁿ is 2-to-1 with f(x) = f(x') iff x' = x ⊕ s for an unknown nonzero s), the circuit (H^{⊗n} on the input, U_f into an n-qubit output register, measure the output (or not — principle of implicit measurement), H^{⊗n} on the input, measure), the post-oracle state and the effect of measuring the output register (derive: the input collapses to (|x₀⟩ + |x₀ ⊕ s⟩)/√2), the final measurement yields a uniformly random y with y·s = 0 (derive: the amplitude of y is ∝ (−1)^{x₀·y}(1 + (−1)^{s·y})), so each run gives one linear equation over GF(2); collecting n − 1 linearly independent equations and solving for s by Gaussian elimination over GF(2) (LA-2 over the field Z₂ — note that linear algebra works over any field, LA-3's axioms; derive the elimination on a small example), the expected number of runs is O(n) (derive: the probability that n − 1 random vectors from an (n−1)-dimensional space are independent is bounded below by a constant ≈ 0.289 — derive the product Π(1 − 2^{k−(n−1)}) and its bound, or the simpler argument that each new vector is independent with probability ≥ 1/2), so quantum O(n) queries; THE CLASSICAL LOWER BOUND: any randomized classical algorithm needs Ω(2^{n/2}) queries (derive via the birthday argument: until a collision f(x) = f(x') is found, the queries reveal nothing about s beyond excluding the pairwise XORs of queried points; the probability of a collision among k queries is ≤ k²/2ⁿ — F4's birthday bound), hence an EXPONENTIAL SEPARATION against randomized algorithms — the first real one; Simon's problem as an instance of the hidden subgroup problem (the subgroup {0, s} of Z₂ⁿ; f is constant on cosets; Fourier sampling over the group returns elements of the orthogonal complement — say this sentence carefully because QC-5's period finding is the same with Z_N); QUERY LOWER BOUNDS for quantum algorithms in one page: the polynomial method stated (a T-query quantum algorithm's acceptance probability is a polynomial of degree ≤ 2T in the input bits — state with the induction idea), the consequence that computing OR (unstructured search) needs Ω(√N) queries (QC-6's Grover is optimal — preview), and that quantum speedups for total functions are at most polynomial (Beals et al. — state), so exponential speedups need promises/structure (the thread from Deutsch–Jozsa to Simon to Shor); WHERE THE SPEEDUP COMES FROM: interference (amplitudes with signs cancel) + structure (the Fourier transform concentrates amplitude on the structure) — the honest summary, and why "trying all inputs in parallel" is the wrong picture (measuring after the oracle without the second Hadamard gives a random x and f(x), no better than classical — show this explicitly).

Worked examples (≥8): the Hadamard transform H^{⊗2}|10⟩ written out with all four signs; Deutsch's algorithm for f(x) = x step by step; Deutsch–Jozsa for n = 2 with a balanced f (the |00⟩ amplitude cancels to 0, term by term); the randomized classical error bound for Deutsch–Jozsa after 3 queries; Bernstein–Vazirani for s = 101 with the state after each layer; Simon's algorithm for n = 3, s = 110: the post-oracle collapse for one x₀ and the possible outputs y (all with y·s = 0), then solving for s from two equations over GF(2); the birthday bound on k = 2^{n/2} queries; the measure-after-oracle "no speedup" calculation.

Project (numpy; QC-2's simulator): the Hadamard transform as a matrix (assert H^{⊗n} = the ±1 character matrix / 2^{n/2} and its self-inverse) and as a fast Walsh–Hadamard transform (implement the butterfly in O(n2ⁿ) — the F3 FFT analogue; assert agreement); phase kickback with the |−⟩ ancilla (assert the ancilla factorizes out); Deutsch and Deutsch–Jozsa for all constant functions and 50 random balanced functions with n = 1..8 (assert the |0ⁿ⟩ probability is 1 or 0); the classical randomized Deutsch–Jozsa error vs queries (Monte Carlo vs 2^{1−k}); Bernstein–Vazirani for random s with n up to 12 (assert exact recovery in one query) vs the classical n-query algorithm; Simon's algorithm end to end: build U_f for a random 2-to-1 function with hidden s (n = 3..8), run until n − 1 independent equations are collected, solve over GF(2) (implement Gaussian elimination mod 2), assert s recovered; the distribution of the number of runs needed vs n (assert mean O(n)) against the independence-probability formula; the classical birthday-attack baseline: queries until collision vs n (log-plot, slope ½ — assert), the exponential gap figure (the signature figure); the measure-after-oracle experiment showing no advantage; the polynomial-method picture for n = 2: compute the acceptance probability of a 1-query algorithm as a polynomial in the input bits and verify its degree ≤ 2. "Your turn": the recursive Bernstein–Vazirani problem at depth 2; a hidden-subgroup instance over Z₂ⁿ with a subgroup of size 4 (two hidden strings) and the modified linear algebra; implement the phase oracle directly (diagonal ±1) and show it is the same circuit as the bit oracle with |−⟩.

§8 honest: Deutsch–Jozsa's exponential speedup evaporates against randomized classical algorithms and the module says so up front; the Hadamard transform's sign formula (−1)^{x·y} is the thing to make automatic — everything else follows; Simon's analysis requires linear algebra over GF(2), which is LA-3 over a different field, and students who think vectors must be real will stall; the classical lower bound is a birthday argument, not magic; "quantum parallelism" (evaluating f on all inputs at once) is a misleading slogan — the measure-after-oracle experiment shows why; query complexity is a model where separations are provable, and real-world speedups require that the oracle be efficiently implementable (Shor's is; many aren't).
